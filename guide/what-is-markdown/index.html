Markdownとは？ 30秒でわかる概要

Markdownは、簡単な記号で文章の構造（見出し・強調・箇条書きなど）を表現できる書き方のルールです。正式には「軽量マークアップ言語」と呼ばれ、2004年にジョン・グルーバー氏によって考案されました。

ポイントは次の2つです。

  • 書くときはただのテキスト — メモ帳でもスマホでも、どんな環境でも書ける
  • 表示するときは整形されたドキュメント — 対応ツールに通すと、見出しや太字が反映された美しい文書になる

ファイルの拡張子は .md が使われます。GitHubのプロジェクトに必ずある「README.md」の「.md」はMarkdownの略です。

百聞は一見にしかず：Markdownの実例

次の左側のようなテキストを書くと、右側のように表示されます。

書き方（Markdown）
# 会議メモ

## 決まったこと

- 次回リリースは **10月15日**
- 担当は *田中さん*

詳細は [仕様書](https://example.com) を参照。
表示結果

会議メモ

決まったこと

  • 次回リリースは 10月15日
  • 担当は 田中さん

詳細は 仕様書 を参照。

記号はたったこれだけ：# が見出し、- が箇条書き、** で挟むと太字、[テキスト](URL) がリンクです。装飾ボタンを探してクリックする代わりに、キーボードから手を離さずに文書の構造を作れます。

Markdownのメリット・デメリット

メリット

  • 速い — 装飾のためにマウス操作が不要。書くことに集中できる
  • どこでも書ける・開ける — 中身はただのテキスト。専用ソフトがなくても読み書きできる
  • 持ち運びやすい — WordファイルやGoogleドキュメントと違い、サービス間のコピペで書式が壊れにくい
  • バージョン管理と相性が良い — テキストなのでGitで差分管理でき、エンジニアの標準になっている
  • 将来も読める — 特定企業のファイル形式に依存しないため、10年後でも開けなくなる心配がない

デメリット

  • 方言（フレーバー）がある — サービスによって対応記法が微妙に異なる（GitHub Flavored Markdownなど）
  • 複雑なレイアウトは苦手 — 文字色の変更、セル結合、細かい配置指定などは標準記法にはなく、HTML/CSSの補助が必要
  • 表示確認に変換が必要 — 書いたままでは記号が見えるだけなので、プレビュー環境があると便利
3つ目のデメリットを解決するのがMarkdownビューアーです。貼り付けるだけで表示結果を確認でき、フォントや余白を調整してブログ用のCSS/HTMLとして持ち出せます。

Markdownが使われる場所

Markdownは「エンジニアのもの」と思われがちですが、いまや職種を問わず使われています。

分野サービス・用途の例
開発GitHub / GitLab（README・Issue・PR）、各種ドキュメントツール
メモ・ノートNotion、Obsidian、Bear、Typora
チャットSlack、Discord、Microsoft Teams（一部記法）
ブログ・技術記事Qiita、Zenn、はてなブログ、note（一部）、WordPress（プラグイン）
AIチャットChatGPT、Claude、Geminiの回答はMarkdown形式で出力される

特に近年はAIチャットの回答がMarkdownで出力されるため、「AIの回答をコピーしたら # や ** だらけだった」という形でMarkdownに出会う人が増えています。そのままビューアーに貼り付ければ、整形された状態で読めて、そのままブログ等に転用できます。

MarkdownとHTMLの関係

Markdownは、最終的にHTML（ウェブページを構成する言語）に変換されて表示されます。たとえば # 見出し は <h1>見出し</h1> に、**太字** は <strong>太字</strong> に変換されます。

つまりMarkdownは「HTMLを速く・読みやすく書くための短縮記法」と言えます。この性質のおかげで、Markdownの中にHTMLタグを直接書くことも可能です。標準記法でできないこと（文字色の変更、画像のサイズ指定、セル内改行など）は、HTMLタグで補うのが定石です。

よくある質問

Markdownを覚えるのは難しいですか？

基本の6記法だけなら30分もかかりません。日常的に使う記法は限られているので、まず見出し・太字・箇条書きの3つから使い始めるのがおすすめです。

.mdファイルをもらったのですが、どうやって開けばいいですか？

中身はテキストファイルなのでメモ帳でも開けますが、記号がそのまま表示されます。整形された状態で読むには、当サイトのビューアーにファイルをドラッグ＆ドロップしてください。インストール不要で、内容が外部に送信されることもありません。

MarkdownとWord、どちらを使うべきですか？

印刷レイアウトが重要な文書（契約書・チラシ等）はWord、構造が中心の文書（議事録・手順書・技術メモ・ブログ原稿）はMarkdownが向いています。共同編集やバージョン管理をするならMarkdownが圧倒的に扱いやすいです。

サービスごとに記法が違うのはなぜですか？

元祖Markdownの仕様が最小限だったため、各サービスが表・チェックボックスなどを独自拡張してきた歴史があります。GitHubの拡張（GFM）が事実上の標準です。よく使うサービスでの挙動の違いは改行の記事でも解説しています。
